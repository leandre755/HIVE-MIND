# workflow
- Use graphify systematically for planning and execution to avoid omissions and track progress. Confidence: 0.75
- Before making modifications, restore context by reading project-level GCC files (e.g., `.GCC/main.md` and `.GCC/resume.md`). Confidence: 0.65
- Prefers atomic commits grouped by semantic goal/purpose. Confidence: 0.85
- ESLint exit code 1 (errors) is tolerated and should not block continuation of automation. Confidence: 0.70
- When delegating implementation to smaller/cheaper models, produces very detailed plans to prevent mistakes. Confidence: 0.65
- Before modifying any file, measures the ESLint and TypeScript baseline (aggregated by file AND by rule) to understand the scope of work and track progress numerically. Confidence: 0.90
- Before removing exports or dead code, verifies the symbol is truly unused by searching all imports across the entire codebase with grep, not just the current file's imports. Confidence: 0.80
- Believes pre-commit hooks are the ultimate quality gate: --no-verify is tolerated only as a temporary concession during phased cleanup, with a hard deadline for full enforcement where all code (agent or human) must pass 100% clean. Confidence: 0.80
- When faced with a choice between completing a complex refactoring vs. accepting residual issues and deferring follow-up, prefers to push through and finish thoroughly rather than leaving work for later. Confidence: 0.80
- When working in parallel with other agents/contributors, checks git status for file collisions with active branches before starting modifications to avoid conflicts. Confidence: 0.70
- Confirms scope and critical decisions with the user before proceeding with irreversible operations (e.g., modifying Git remotes, pushing, handling exposed secrets/tokens). Pauses execution rather than assuming. Confidence: 0.70
- Prefers narrow, specific allow/deny rules targeting exact file paths and command patterns rather than broad catch-all rules in tool configuration — only the explicitly listed actions should be included, no extrapolation. Confidence: 0.75
- Uses Conventional Commit format (`type: description`) with trailers (e.g., `Co-authored-by`) for commit messages. Confidence: 0.70
- Scans the staged diff for secrets (GitHub PATs, AWS keys, private keys, OpenAI keys) via `git diff --cached -G` before committing, and aborts if any are found. Confidence: 0.80
- Reads all untracked files before staging them with `git add -A` to verify no secrets, credentials, or unnecessary local artifacts are accidentally committed. Confidence: 0.75
- After any code fix during runtime debugging, runs `npx tsc --noEmit` as a verification gate before retrying — fix, verify statically, then retry runtime. Confidence: 0.65
